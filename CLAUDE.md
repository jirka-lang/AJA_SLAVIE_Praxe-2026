## Project Overview

Student internship schedule portal ("Praxe 2026") for SK Slavia Praha youth department. Token-protected static web app displaying individual student practice schedules. No frameworks — vanilla HTML/CSS/JS frontend with Python backend for data processing.

## Architecture

```
[Praxe 2026.xlsx] ──→ [rozvrh_praxe.py] ──→ [data.json] ──→ [index.html + app.js]
  (source data)        (scheduler)           (generated)       (static frontend)
```

**Two-phase system:**
1. **Python backend** (`rozvrh_praxe.py`): Reads Excel, schedules activities to students based on availability/capacity/constraints, outputs `data.json` + updated Excel sheets
2. **Static frontend** (`index.html`, `app.js`, `style.css`): Reads `data.json`, authenticates via URL token (`?t=TOKEN`), renders dashboard

## Key Commands

### Regenerate schedules from Excel
```bash
python3 rozvrh_praxe.py "Praxe 2026.xlsx"
```
This overwrites `data.json` and adds 4 output sheets to the Excel file. Source sheets ("Program činností", "DBF studenti") are preserved.

### Local development
```bash
python3 -m http.server 8080
# Open http://localhost:8080/?t=d0a33c9d (any valid token from data.json)
```

### Deploy to GitHub Pages
```bash
git add . && git commit -m "description" && git push
# Pages auto-builds from main branch
```

## Frontend Architecture

**Two views:** Gate (invalid/missing token) and Dashboard (authenticated).

`app.js` key flow: `init()` → fetch `data.json` → validate token from URL → `showDashboard()` or `showGate()`.

**Responsive design:** Desktop uses `<table class="schedule-table">`, mobile (<600px) uses `<div class="schedule-cards">` with card layout. Both are generated by `renderSchedule()` into separate DOM containers (`#schedule-table` and `#schedule-cards`).

**Activity types** are color-coded via CSS classes: `type-asistence`, `type-turnaj`, `type-vyucovani`, `type-prednaska`, `type-vzorova`, `type-volno`.

## Backend Architecture (rozvrh_praxe.py)

**Data models:** `Activity` (name, dates, capacity, type, organizer) and `Student` (name, school, date range, repre conflicts).

**Scheduling algorithm:** Iterates weekdays in student's date range, assigns activities respecting capacity limits, time constraints (8:00-15:00), and national team ("repre") conflicts.

**Outputs:** `data.json` for frontend + Excel sheets (Analýza potřeb, Rozvrh-Matice, Rozvrh-Detail, Souhrn).

**Token generation:** MD5 hash of student info → 8-char hex token used as URL parameter.

## Data Format (data.json)

```json
{
  "students": {
    "TOKEN": {
      "name": "...", "school": "...", "start": "YYYY-MM-DD", "end": "YYYY-MM-DD",
      "schedule": { "YYYY-MM-DD": [{ "time": "HH:MM-HH:MM", "activity": "...", "type": "...", "organizer": "...", "contact": "..." }] },
      "stats": { "total_hours": N, "total_days": N, "activities_count": N }
    }
  }
}
```
